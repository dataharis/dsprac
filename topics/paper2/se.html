1. Master Formula Sheet (TGT & PGT Numericals)

  • • McCabe Cyclomatic Complexity: V(G) = E - N + 2P (For single program P=1: V(G) = E - N + 2 = Predicates + 1 = Regions)
  • • Standard BVA Test Cases (n inputs): 4n + 1
  • • Robust BVA Test Cases (n inputs): 6n + 1
  • • Worst-Case BVA Test Cases: 5^n (Robust Worst-Case = 7^n)
  • • Basic COCOMO Effort & Time: E = a(KLOC)^b PM; D = c(E)^d Months (Organic: a=2.4, b=1.05; Semi: a=3.0, b=1.12; Embedded: a=3.6, b=1.20)
  • • Function Point (FP): CAF = 0.65 + 0.01 × ΣFi (Range 0.65 to 1.35); FP = UFP × CAF
  • • PERT Expected Duration: te = (to + 4tm + tp) / 6; Std Dev σ = (tp - to) / 6
  • • Reliability & Availability: MTBF = MTTF + MTTR; Availability = MTTF / (MTTF + MTTR) × 100%

2. Cohesion & Coupling Golden Order (PYQ 2021 Q.148)

Ideal Modular Design: HIGH Cohesion (intra-module unity) + LOW / LOOSE Coupling (inter-module independence).

Cohesion (Best → Worst): 1. Functional (Best) → 2. Sequential → 3. Communicational → 4. Procedural → 5. Temporal → 6. Logical → 7. Coincidental (Worst).
Coupling (Best/Loosest → Worst/Tightest): 1. Data (Best) → 2. Stamp → 3. Control → 4. External → 5. Common (Global vars) → 6. Content (Worst).

3. Top 12 One-Liners from DSSSB TGT CS Answer Keys

  • 1. Verification: "Are we building the product right?" (Static reviews, no code execution).
  • 2. Validation: "Are we building the right product?" (Dynamic testing against user expectations).
  • 3. Pareto Principle in SE: 80% of defects come from 20% of modules (2017 Q.168).
  • 4. Highest SDLC Cost Phase: Maintenance (~60%–70% of total budget; Perfective ~50% is largest share).
  • 5. Spiral Model (Barry Boehm): Risk-driven Meta-Model with 4 quadrants & incremental releases (2021 Q.145).
  • 6. DFD (Data Flow Diagram): Also called a Bubble Chart (2021 Q.144); Context Diagram = Level-0 DFD (1 process bubble).
  • 7. SRS Document: Acts as a Black-Box Specification (specifies WHAT, not HOW — 2021 S3 Q.47).
  • 8. Equivalence Partitioning & BVA: Core Black-Box (Behavioral) testing techniques (2017 Q.167, 2021 Q.143).
  • 9. Top-Down vs Bottom-Up Integration: Top-Down uses Stubs; Bottom-Up uses Drivers.
  • 10. Alpha vs Beta Testing: Alpha = at developer's site (controlled); Beta = at customer's site (real environment).
  • 11. ISO 9126 6 Quality Factors: Functionality, Reliability, Usability, Efficiency (2023 Q.23), Maintainability, Portability.
  • 12. Brute Force Debugging: Most common and least efficient debugging approach (memory dumps & print statements — 2021 S3 Q.54).

4. Process Models & UML Quick Comparison

  • • Classical Waterfall: Oldest linear sequential model (2023 Q.17); best for stable requirements; customer sees working code only at the end.
  • • Prototyping Model: Best when requirements/UI are unclear upfront.
  • • RAD Model: High-speed adaptation delivering complete system in 60–90 days using reusable components.
  • • UML Structural (Static): Class, Object, Component, Deployment, Package.
  • • UML Behavioral (Dynamic): Use Case, Sequence, Collaboration, Statechart, Activity.
  • • Use Case <<include>> vs <<extend>>: Include = Mandatory; Extend = Optional conditional behavior.
  • • Aggregation vs Composition: Aggregation = Hollow Diamond ($\diamond$, weak lifecycle); Composition = Filled Black Diamond ($\blacklozenge$, strong lifecycle).
